# ADR-0008 — Storage Wiring for the CTEM Loop and Evidence-Based Reporting

**Status:** Accepted
**Date:** 2026-08-12
**Deciders:** Manus (author), RISKX spec §§9, 24, 44, 48
**Related:** ADR-0003 (SQLite selection), ADR-0009 (CI pinning)

## Context

storage-v1 (`internal/storage`) implemented the SQLite schema (`assets`, `findings`, `evidence`, `relationships`, `riskscores`) in v0.1, but no CLI command wrote to or read from it. All `riskx discover`/`riskx vuln`/`riskx risk` outputs were JSON-only in-memory. This breaks the CTEM loop in three ways:

1. **Phase 6 reporting needs durable findings.** An executive report generated after a scan must reflect what was actually observed, not a re-run of live discovery.
2. **Provenance requires stable records.** Spec §44 requires evidence to survive between runs; in-memory-only outputs lose that guarantee.
3. **Downstream consumers need a stable input.** `riskx report summary` and the SARIF/CSV/JSONL exporters need a source of truth that is not a fresh network call.

## Decision

Wire storage-v1 into every analysis command with an explicit opt-out policy, and add the reporting/export and safe-validation commands that consume the store:

1. **Default store path** `~/.riskx/riskx.db` (file 0600, parent 0700, pure-Go SQLite driver per ADR-0003). The path is overridable via `--data` flag and `RISKX_DATA` env (flag wins over env; precedence documented in help). `--no-data` disables persistence for that run.
2. `riskx discover` writes every discovered asset via `Store.PutAssets` after in-memory processing. On any storage error the discovery output is unaffected (read-only contract) but the CLI warns on stderr; the run does not silently lose evidence.
3. `riskx vuln` writes generated findings and evidence via `PutFindings` + `PutEvidence` per asset.
4. `riskx risk` writes computed `RiskScore` per asset via `PutRiskScore`.
5. `riskx validate` (new) performs safe read-only validation — real DNS resolution, TLS handshake observation, HTTP probe — and records outcomes (success or a concrete failure) into the store as evidence. A TLS/HTTP failure is recorded as evidence of the failure, never as an inferred attack surface.
6. `riskx cloud discover` (new) uses SigV4-signed AWS query APIs (STS GetCallerIdentity, EC2 DescribeInstances, S3 ListBuckets, IAM ListUsers/GetAccountSummary) to add cloud asset evidence to the store. Only read-only query APIs are callable; credentials via the standard AWS env vars; the SigV4 implementation was cross-verified byte-for-byte against the AWS SDK (botocore) reference signer on the canonical string-to-sign.
7. `riskx report summary` reads assets + findings + risk scores from the store. Sections that cannot be computed from stored data are listed as *deferred* (e.g., remediation guidance beyond stored recommendations), never fabricated.
8. `riskx export jsonl|csv|sarif` writes stored findings to the requested format. SARIF output is 2.1.0 and was validated against the official OASIS Standard + Errata 01 schema (stored under `docs/research/schemas/`).
9. Database errors surface explicitly (`storage.Err*` types for corrupted DB / schema mismatch). No silent data loss per spec §24.
10. **No schema migrations in v0.2** (storage-v1 frozen). A mismatched `schema_version` in the DB file produces an explicit error rather than auto-migrating; migration design is tracked for a later phase.

## Defects fixed during wiring (observed, not guessed)

The SQLite wiring surfaced three defects found by running the wired tests; each received a regression test:

| Defect | Root cause | Fix |
| --- | --- | --- |
| SQLite error on storing findings | Column named `references` collides with the SQLite token parser | Renamed to `finding_references` in schema and mapper |
| Time scanning panic / spurious rows | `time.Time` scanned without pointer semantics | Pointer-scan semantics for all timestamp columns |
| Store close during query | `db.Close()` ran before deferred query rows were consumed | Store lifecycle moved to the CLI runner teardown |

## Consequences

- Evidence survives between runs; `riskx report summary` and all exporters become evidence-based.
- `riskx validate` and `riskx cloud discover` add the **Validate** and cloud **Discover** stages of the CTEM lifecycle under the same no-guessing contract.
- Disk IO added to the hot path; mitigated by batching writes into a single transaction at command end.
- CI adds storage tests (0700/0600 permissions, schema-version mismatch handling, five-table round-trip).
